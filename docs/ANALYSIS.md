# تحليل خط الأساس

## حالة المشروع قبل التعديلات

- المشروع قائم على React 19 وTypeScript وVite، مع React Router 7 وTanStack Query 5 وZustand.
- طبقة الطلبات موحدة في `src/api`، وعقد الخدمة موثق في `docs/openapi.yaml`. يوجد mock مركزي داخل `src/api/mocks` ويُفعّل بمتغير `VITE_USE_MOCKS`.
- الشاشات الموجودة: تسجيل الدخول، لوحة الطبيب، لوحة الاستقبال، سجل اليوم، وقاعدة بيانات المرضى. توجد وظائف الكشف والوصفة والطباعة والإملاء الصوتي والتاريخ المرضي.
- الدوران الحالي محصور في `DOCTOR` و`RECEPTIONIST`. مخزن الدخول يبدأ بجلسة تجريبية افتراضية، ومبدّل الدور يغيّر المستخدم محليًا دون مصادقة. المسارات المحمية لا تخصص الأدوار، والرئيسية تختار بين لوحتي الطبيب والاستقبال.
- يوجد مكوّن Sidebar قديم بعناصر تربط عدة وجهات غير منفذة بمسار سجل اليوم. الرأس الحالي يعرض تنقلًا أفقيًا على الكمبيوتر وقائمة علوية منسدلة على الشاشات الأصغر.
- تعتمد اللوحات وسجل اليوم على بيانات الزيارات، وتعتمد قاعدة المرضى على API المرضى؛ الاستقبال والطبيب يعيدان جلب الطابور دوريًا. لا توجد حاليًا واجهة إحصاءات موحدة، أو لوحة مدير، أو Demo Mode مركزي، أو إعدادات Playwright/E2E، ولا سكريبتا `lint` و`e2e` في `package.json`.
- اختبار Vitest الحالي يحتوي ملفًا واحدًا و4 اختبارات.

## فحوصات خط الأساس

نُفذ `npm ci` بنجاح، ثم `npm run build` و`npm test` بنجاح. نتيجة الاختبار: ملف واحد و4 اختبارات ناجحة. ظهر تحذير Vite/Node عن استخدام `shell: true` في سكريبت البناء، وتحذير npm عن سكريبت تثبيت esbuild غير الموافق عليه، دون فشل للأوامر.

## نقاط يجب الحفاظ عليها

- توسيع `src/api` وعقد OpenAPI بدل استبدالهما.
- استخدام TanStack Query والـmock المركزي كمصدر بيانات للشاشات.
- الحفاظ على وظائف الكشف، المسودات والاعتماد، الوصفات والطباعة، التاريخ المرضي، والإملاء الصوتي.
- إزالة مسارات التنقل غير المنفذة من الواجهة، وعدم عرض مؤشرات إحصائية قبل توفير استعلامات API فعلية لها.
- عدم اعتبار اختيار الدور في الواجهة مصادقة أو صلاحية حقيقية.
