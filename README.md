# كلينيكسيا | CLINICXIA
نظام الإدارة الطبية وعيادات الكشف المتكاملة (الواجهة الأمامية الإنتاجية)
Production-grade Clinic Management System Frontend (Arabic, RTL)

---

## المميزات الرئيسية (Key Features)

- صفحة ترحيب عربية تعرض مساحات الطبيب والاستقبال والمدير ومؤشرات مجمعة من API.
- جلسات وأدوار Doctor وReceptionist وAdmin؛ اختيار الدور في رابط الدخول اقتراح للواجهة، والتحقق الفعلي يأتي من الجلسة والـAPI.
- تنقل أفقي وقائمة منسدلة علوية على الشاشات الأصغر، دون Sidebar.
- لوحة مدير تعرض مؤشرات النظام وقوائم الأطباء والموظفين المتاحة عبر API.

### 1. إدارة الطابور الحي والاستقبال (Reception & Live Queue)
- لوحة تحكم ذكية بإحصائيات حية (حالات اليوم، بالانتظار، داخل الكشف، مكتمل).
- مزامنة لحظية بين الاستقبال والطبيب عبر استعلامات TanStack Query التلقائية.
- تسجيل كشف جديد مع بحث فوري عن المرضى، واكتشاف تكرار أرقام الهواتف تلقائياً.
- سجل اليوم الشامل مع فلاتر الحالة وطباعة تقرير الحالات اليومية.

### 2. لوحة تحكم الطبيب ونموذج الكشف (Doctor Dashboard & Examination)
- قائمة بالحالات الموجهة للطبيب مع إبراز فوري للمريض الموجود داخل غرفة الكشف.
- شريط تحذيري أحمر بارز لحساسية الأدوية وتنبيه للأمراض المزمنة في كل شاشات المريض.
- نموذج كشف طبي متكامل من 7 حقول رئيسية مع حفظ مسودة تلقائي (Autosave).
- اعتماد وقفل الكشف الطبي لمنع التعديل غير الموثق، مع إمكانية إضافة استدراكات طبية موثقة (Addenda).
- قسم قابل للطي داخل شاشة الكشف لعرض تاريخ الزيارات السابقة.

### 3. التوثيق والإملاء الصوتي الذكي (Voice Documentation)
- دعم اختصار لوحة المفاتيح العالمي `F2` لبدء وإيقاف الإملاء الصوتي فوراً.
- اختيار يدوي للغة الإملاء (عربي `ar-EG` / إنجليزي `en-US`) دون خلط عشوائي.
- معمارية مجردة تدعم الإرسال لخادم المعالجة (`BackendTranscriptionProvider`) مع بديل المتصفح المباشر (`BrowserSpeechProvider`).
- إدراج النص عند موضع المؤشر في الحقل النشط مع دعم التراجع الفوري (Undo).

### 4. الروشتة الطبية والطباعة الرسمية (Prescription & A4 Print)
- تحرير وحذف الأدوية بجرعاتها وتعليمات استخدامها.
- نافذة معاينة وطباعة رسمية بنظام مقاس الورق A4 القياسي (`@media print`) تدعم الطباعة المباشرة والحفظ كملف PDF.

### 5. حماية الخصوصية والأمان (Security & Data Protection)
- عدم تخزين بيانات المرضى أو الصوتيات المسجلة نهائياً في التخزين المحلي للمتصفح.
- جلسة المستخدم والتوكن محفوظة في الذاكرة الحية فقط.
- فصل كامل للصلاحيات بين الطبيب وموظف الاستقبال.

## المتطلبات والتثبيت (Setup & Run)

### المتطلبات الأساسية
- Node.js >= 20.x
- npm >= 10.x

### التثبيت والتشغيل المحلي
```bash
# تثبيت الحزم
npm install

# تشغيل بيئة التطوير
npm run dev

# فحص الأنواع (TypeScript Strict)
npm run typecheck

# فحص قواعد الشيفرة
npm run lint

# تشغيل الاختبارات
npm test

# اختبارات المتصفح الشاملة
npm run e2e

# بناء النسخة الإنتاجية
npm run build
```

## متغيرات البيئة (Environment Variables)
انسخ `.env.example` إلى `.env`:
```env
# رابط واجهة برمجة التطبيقات
VITE_API_BASE_URL=/api

# تفعيل السيرفر الوهمي للتجربة والتطوير (true / false)
VITE_USE_MOCKS=true

# الواجهة السريعة وإعادة ضبط بيانات العرض (اجعلها true في بيئة العرض فقط)
VITE_DEMO_MODE=false

# مزود خدمة تحويل الصوت (backend أو browser)
VITE_TRANSCRIPTION_PROVIDER=browser
```

## حسابات التجربة السريعة (Demo Accounts)
- فعّل `VITE_DEMO_MODE=true` لإظهار أزرار الدخول السريع وجولة العرض وإعادة الضبط للمدير.
- **الطبيب:** `doctor.demo`، **الاستقبال:** `reception.demo`، **المدير:** `admin.demo`.
- كلمة المرور للحسابات التجريبية: `123456`.
- بيانات المرضى والحسابات في الـmock مصطنعة ومخصصة للعرض، وتُعاد من حساب المدير.
